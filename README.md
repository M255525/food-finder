# 巷口美食通

台北/新北地區的三餐美食建議工具，主要設計給樂齡與上班族使用。

🔗 **線上使用**：<https://m255525.github.io/food-finder/>

## 這是什麼

依你輸入的地址／地標，或選擇的捷運站，加上餐期、距離偏好、預算、美食類型、人數與自由文字需求，請你自選的 AI（語言模型）扮演熟悉台北/新北美食的在地朋友，生成一份建議清單。

**只需要一把語言模型（LLM）的 API 金鑰即可使用，不需要申請 Google 地圖服務、不需要綁信用卡**——這是刻意的設計取捨：目標使用族群是樂齡與上班族，門檻越低越好。也因為如此，建議清單是 AI 依既有知識生成的文字，**不是即時查詢的真實資料**，店家可能已歇業、搬遷，地址或距離可能不準確，介面上多處都會提醒你出發前務必自行查證。

## 功能

- **兩種地點輸入方式**：輸入地址／地標（純文字），或先選捷運路線再選站別（149 站，涵蓋台北捷運＋新北捷運環狀線／安坑輕軌／淡海輕軌／三鶯線，資料取自 OpenStreetMap，避免一次列出全部站名造成混亂）
- **搜尋條件**：餐期（早/午/晚餐）、距離偏好（300公尺/500公尺/1公里，AI 估計值）、參考人數、預算、美食類型（可複選）、自由文字需求
- **AI 生成建議清單**：每家店顯示類型、大概距離、價位、評價星等（AI 沒把握會誠實標示「沒有」，不虛構數字）、位置描述、推薦理由，並附「上網查證」連結方便確認店家是否還在營業
- **繼續搜尋**：對第一批建議不滿意，可以按「都不滿意？繼續搜尋其他餐飲」，AI 會排除已列出的店家生成新的一批，新舊批次會一起保留、標示「第幾批」
- **無障礙文字大小**：右上角「小／中／大」可即時調整全站文字大小，設定會記住；互動元件的觸控熱區也會隨字級放大
- **BYOK**：支援 Claude／OpenAI／Gemini／OpenRouter 四選一，API 金鑰只存在瀏覽器 localStorage，不經過任何後端伺服器

## 怎麼用

1. 開啟 <https://m255525.github.io/food-finder/>
2. 按右上角「⚙️」，選一個 AI 服務商，貼上你自己申請的 API 金鑰（申請網址見下方或 [manual.html](https://m255525.github.io/food-finder/manual.html)）
3. 選餐期、輸入地址或選捷運站、選距離偏好，視需要調整其他篩選條件
4. 按「請 AI 幫我推薦」

詳細操作說明（含金鑰申請步驟、常見問題）見 [manual.html](https://m255525.github.io/food-finder/manual.html)。

## 技術架構

純前端單檔工具，**沒有任何建置流程、框架、npm 依賴、後端伺服器**：

| 項目 | 做法 |
|---|---|
| AI 推薦生成 | 瀏覽器直接 `fetch` 你選擇的 LLM 服務商官方 API（無後端代理） |
| 金鑰儲存 | `localStorage`，只在使用者自己的瀏覽器裡 |
| 捷運站資料 | 靜態 JS 資料檔，座標取自 OpenStreetMap Overpass API |
| 頂部跑馬燈 | 與工作區其他工具共用同一個公告來源（可選、失敗不影響主功能） |

## 本機開發

不需要任何建置工具或安裝依賴，純靜態檔案：

```bash
git clone https://github.com/M255525/food-finder.git
cd food-finder
python -m http.server 8000
```

開啟 `http://localhost:8000`。

## 檔案結構

## 隱私與資料

本 repo 公開的只有程式碼。你填寫的搜尋條件與 API 金鑰只存在自己瀏覽器的 localStorage；按下「請 AI 幫我推薦」時，這些內容會直接連線送到你選擇的 AI 服務商，不經過本工具作者或任何第三方伺服器。

## 已知限制

- 建議清單完全依賴 AI 既有知識生成，不會查詢任何即時地圖或商家資料庫，可能有幻覺、過時或不準確的內容
- 距離、價位是 AI 的估計值，不是實際測量或查表得出
- 目前僅涵蓋台北市與新北市地區
